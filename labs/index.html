Demos you can open and test yourself

Ten applications that run entirely inside a single browser tab. No server and no build step, and nine of the ten have no dependencies either — just plain HTML, CSS and JavaScript. Rombak is the exception: it vendors SQLite, and says so on its own front page. The code is readable, and nine of the ten run their own assertions the moment they open, so the claims are yours to verify, not merely to trust. Saku is the other exception: it is a share-target demo rather than an engine, and its Engine tab reports what this browser actually supports instead. The same assertions are re-run automatically in CI on every change to the repository, in real Chromium, against the very page you are looking at.

Every piece of data here is fabricated. No real patients, students, employees, suppliers or companies — all of it is generated from seed numbers inside the code. No valid national ID, tax, student or social-security numbers. Not a single page sends data anywhere; nine of the ten show a network-call counter that stays pinned at zero. Saku has no counter — it is a share-target demo, and what it captures is written to IndexedDB on this device and goes nowhere.

Information systems

The five sectors most often commissioned in the Indonesian market. What's proven here isn't the ability to build CRUD, but whether the domain rules are correct — medical-record numbering, schedule conflicts, inventory cost of goods, PPh 21 income tax, and the accounting equation.

379 assertions

A clinic information system — queueing, SOAP medical records, ICD-10 codes, prescriptions with drug-interaction checks, cashier. The registration, nurse, doctor and pharmacist roles each see a different screen.

The hardest partAn append-only audit trail with a hash chain: corrections are made as addenda that supersede without destroying the original, and a button verifies the chain until it finds the point that was tampered with.

Engineering demos

Five that aren't information systems. They target things that are hard to prove in a line on a CV: a grasp of HTTP, what the web platform can do on a phone, what happens when a schema has to change while the rows are already in it, why a valid signature is not the same thing as a token you should accept, and what two writers do to one balance.

Serobot

187 properties

Two writers race one balance, in real workers on real IndexedDB. A stored column loses updates in silence; an append-only ledger cannot. A rendezvous turns the race into an exact integer, which is what makes any of it assertable at all.

The hardest partNot the threads. The same loss happens on one event loop with no workers at all, and there it is exact — ten writers doing ten increments each produce ten, not a hundred. The cause is a read that spans an await; parallelism only makes it easy to hit.

Sahih

150 properties

Five JSON Web Tokens through a naive verifier and a strict one, on the same bytes. Real RSA-2048, real P-256 ECDSA, real HMAC — all on crypto.subtle, nothing vendored, and the published RFC test vectors checked against the values the RFC prints.

The hardest partEvery token here is valid in the only sense cryptography can offer — the signature checks out — and four of the five are forgeries anyway. The signature is the easy part; everything that decides what a token means sits outside it.

Rombak

262 properties

A real SQLite database in the tab — the engine itself, compiled to WebAssembly — walked forward through nine schema versions against rows that are already in it. Foreign keys, CHECK constraints, partial indexes, STRICT tables, and EXPLAIN QUERY PLAN from the real planner.

The hardest partA table rebuild that commits successfully, passes every integrity check, reports no error anywhere — and has silently deleted rows. The difference between the migration that refuses and the one that destroys is one word in a child table's DDL.

How to read these demos. Nine of the ten have a Tests tab that runs their assertions in front of you, and a network-call counter up top; Saku, the share-target demo, has an Engine tab that probes this browser's capabilities live instead. The numbers shown are computed from the data inside the tab, not read from stored values — that's exactly what's being tested.

These are demos, not finished products, and not medical, tax or accounting advice. Each application's limitations are written plainly in a README.md file inside its own folder.
