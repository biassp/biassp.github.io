Every row on this page is fabricated, and the schema itself enforces it. No patient, staff member, diagnosis, bill or rupiah here is real. Every national identity number is NIK-FIKTIF-… and every insurance number BPJS-FIKTIF-…, both under a CHECK … GLOB that makes a valid-shaped one unstorable; phone numbers carry FIKTIF in the middle; and patient.is_demo is CHECK (is_demo = 1), so the table is structurally incapable of holding a row that claims to be real. The whole database is rebuilt from one seed number and one pinned date every time this page loads, so the figures you see are the figures in the README and you can check them yourself.

This page ships 878 KB of somebody else's code, and that makes a claim on this site wrong.

The suite index says 0 dependencies. This lab vendors SQLite — compiled to WebAssembly by the sql.js project, MIT-licensed, checked into the repository — and that sentence is now false, not nuanced. It has been corrected everywhere it appears rather than reworded into something technically defensible.

The file is vendor/sqlite-wasm-base64.js. About a fifth of it is pure base64 overhead over the 658,410-byte binary — paid by every visitor, including on a metered phone connection, before any of my own code runs. It is base64 rather than a fetch because fetching the .wasm the normal way is a network request, and every lab on this site ships connect-src 'none' with a counter pinned at zero. That claim is worth more than the overhead. The counter in the header still reads 0 after everything on this page has run, including the export.

It is also the one exception to this site's promise that you can read the source. That file is a single unreadable line and it is roughly a quarter of what this lab ships. node tools/vendor-sqljs.js labs/rombak regenerates all three vendored files and git diff afterwards is empty — which is why sql.js is pinned to exactly 1.14.2 rather than a caret range that would quietly expire. The MIT licence is at vendor/LICENSE and the third-party banner at the top of each generated file is not to be removed.

The Content-Security-Policy on this page is also weaker than on the other seven labs: script-src gains 'wasm-unsafe-eval'. That directive permits WebAssembly compilation and instantiation. It does not permit eval(), new Function(), or inline script. connect-src 'none' — the directive that actually protects the data — is byte-identical to every other lab here.

What this page does not prove

Every limit below is a real one, and none of them is a limit this page could design away.

It is not MySQL, and it is not Postgres. SQLite has one writer, one isolation model, no InnoDB buffer pool, no query cache, no replication, no EXPLAIN ANALYZE, no ALGORITHM=INPLACE, no pt-online-schema-change, no logical-replication cutover, and a planner with a different cost model. The ordering discipline on this page transfers completely — capture the DDL of your indexes and triggers before you drop the table, run the integrity check inside the transaction, know which children cascade, never assume a clean check means a correct migration. The concurrency problem does not transfer at all, and the hardest part of a real migration is doing it while writes are arriving. There is nothing here to write to this database but you.

Durability is not demonstrated. The database is in RAM. There is no WAL, no fsync, no journal on disk. "Atomic" here means the transaction was atomic, not that the file survived a power cut. The twelve-step rebuild protects against a logic error, not against a crash.

The scale is wrong by orders of magnitude. These migrations run in single-digit milliseconds. Lock waits, a rebuild that outruns its maintenance window, a replica falling behind — none of those can appear at this size and none is simulated.

This build is missing things. PRAGMA compile_options is on the Schema tab. FTS5 is absent, so there is no full-text chapter and the ICD-10 search is a plain index. No rtree. No dbstat, so index size is shown as a page_count − freelist_count delta rather than per-index pages. No sqlite_stat4, so ANALYZE produces average rows-per-value and nothing finer. No generate_series, no DELETE … LIMIT.

STRICT is not "no coercion", it is "no lossy coercion". 'abc' and 12.5 are refused in an INTEGER column. '123' still stores as 123 and 12.0 as 12. That is on the Constraints tab as its own row rather than quietly omitted.

The commitment is not an external anchor. audit_commitment makes truncating the tail cost the same as editing the middle. It does not make either impossible: anyone who can write the audit rows can write the commitment. Only a countersigning server or a published daily head hash fixes that, and neither is available to a page that makes no network calls. The append-only triggers are likewise enforcement through SQL and not against someone editing the bytes — and, as v9 shows, not even against a table rebuild.

The polymorphic audit column is a trade-off, not a solution. Three nullable typed columns plus a CHECK that exactly one is non-null buys real foreign keys on all three, at the cost of two always-NULL columns, a coalesce() on every read, and a table rebuild the day a fourth entity type appears. The alternative keeps the table narrow and moves the check into a trigger a bulk load can be told to skip. Both are named on the Constraints tab. This one was taken.

Four defects in this fixture were planted. They are listed on the Migrations tab with what each one is the residue of. The fifth failure — the rebuild that commits and destroys — is not planted: the ON DELETE CASCADE on addendum is correct domain modelling that happens to be a trap, and nothing about it was arranged for this page.

The numbers here will not match the numbers in the README. Every timing is measured on your machine at this moment, as a mean over N runs with N shown. The README's figures are labelled "one run, one machine" and are expected to differ. A lab whose numbers never move is a lab that never ran.

Down-migrations are mostly absent, and that is a position. Two of the nine steps have a real down and it runs. The other seven refuse, with the reason printed. A down that cannot restore what the up dropped is worse than no down, because it advertises a safety that is not there.

What this is for. The CV claims Database Administrator, Infinix Philippines, Oct 2022 – Oct 2023 — ensuring data integrity, running backups, optimizing queries. That is a year of database work with no artifact anywhere on this site. case/bioage claims in prose that every migration there is a guarded additive ALTER TABLE and never a rename or a drop. case/repbout admits a stored balance column that still needs converting to an append-only ledger. Three database claims, all prose, all about repositories nobody can see. This page makes two of the three runnable. It does not demonstrate backups.

A clean integrity check is not evidence of a correct migration. That is the one sentence this page exists to make runnable. Two rebuilds on the Rebuild tab commit, return no error, and leave PRAGMA foreign_key_check returning an empty set: one of them deletes rows, and the other keeps every row and silently removes both append-only triggers. They are two rebuilds of two different tables, because no single one does both — the table that loses rows here carries no trigger to lose, which is itself worth knowing. Every figure on the live-database card is computed twice, once by SQLite's query engine and once by hand-written JavaScript folding raw rows, with both numbers and their difference on screen. That discipline covers the figures and not everything on this page: a plan string and a timing have one route each.

Why the network number matters here. This page ships connect-src 'none' inside a <meta http-equiv="Content-Security-Policy"> tag in its own source, so the browser refuses every outbound connection this document's JavaScript asks for. The wrappers in guard.js close over fetch, XMLHttpRequest, WebSocket, EventSource and sendBeacon and count every attempt, which is why the vendored engine is base64 in a <script> and not a .wasm behind a fetch. Open DevTools; the Network tab stays empty. This is a statement about this page — the CV homepage at biassp.github.io does call the GitHub API for its repository list.
